# Implementation Plan: TODO API CRUD

**Branch**: `001-todo-api-crud` | **Date**: 2026-05-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-todo-api-crud/spec.md`

## Summary

Build a REST TODO API that supports create, read, update, and delete operations on todo items. Each item carries a title, optional description, optional due date, and completion status. The list endpoint supports filtering by completion status and sorting by due date. The implementation uses **FastAPI** with **SQLAlchemy 2.x async** against **SQLite** (`aiosqlite` driver), organized as a **single project with vertical slice architecture**, with **pytest** as the test framework targeting ≥ 90 % coverage. All routes live under `/api/v1/`.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**: FastAPI ≥ 0.111, SQLAlchemy ≥ 2.0 (async), aiosqlite ≥ 0.19, Pydantic v2 ≥ 2.7, pydantic-settings ≥ 2.0, uvicorn ≥ 0.30

**Storage**: SQLite (local file `todo.db`; in-memory `:memory:` for tests) via SQLAlchemy async engine

**Testing**: pytest ≥ 8.0 + pytest-asyncio ≥ 0.23 + httpx ≥ 0.27 (TestClient)

**Target Platform**: Linux / macOS local development server

**Project Type**: web-service (REST API)

**Performance Goals**: All CRUD operations complete in < 500ms under normal single-user load (SC-004)

**Constraints**: < 200ms p95 for simple CRUD on SQLite; no pagination in v1

**Scale/Scope**: Single developer, single SQLite file, no authentication, no concurrent-user requirements

```text
├── __init__.py
├── conftest.py          ← Fixtures: in-memory DB engine, override get_db, TestClient

    ├── test_read_todo.py     ← US-2 acceptance scenarios (list, filter, sort, single-get, 404)

pyproject.toml           ← project metadata + pytest config (asyncio_mode = "auto", cov ≥ 90%)
requirements.txt         ← pinned runtime + dev dependencies
.env.example             ← template: DATABASE_URL, APP_ENV, LOG_LEVEL
.gitignore               ← todo.db, .venv/, __pycache__/, .env, .coverage, htmlcov/

```

**Structure Decision**: Single-project vertical slice. The `todos/` directory is the sole feature slice containing all five modules (model, schemas, repository, service, router). The `shared/` package holds only cross-cutting infrastructure that is not specific to the todos domain. This aligns with the constitution's `Depends` injection requirement and keeps each slice independently testable.
